# ADR 0040: MCP read tools through native typed bindings

- Status: Accepted for Phase 11A implementation; review pending
- Date: 2026-10-02

## Decision

Add a stdio client adapter to `runveil_tools`, using the official Python MCP SDK.
Keep the core runtime, registry, execution store and approval workflows unchanged.
Use the SDK's v1 maintenance line, locked to 1.30.0 with `>=1.30,<2`, to bound this
integration to its inspected `ClientSession` API and local-only schema reference
validation. A major SDK upgrade is a separate compatibility review. See the
[official maintenance-line documentation](https://py.sdk.modelcontextprotocol.io/v1/).

The operator supplies the executable, arguments and environment outside model
requests and persisted configuration. Initialize the SDK session, require tools
capability, and discover one complete catalog under a deadline. Reject pagination,
duplicate names, more than 128 entries or a catalog larger than 64 KiB. No partial
catalog, dynamic refresh, server instructions or automatic tool registration.

Each selected remote tool must exactly match the input and output JSON schemas
generated by operator-owned Pydantic contracts, including titles and defaults.
The operator provides a local `mcp.*` name and description and asserts read-only
behavior. Server descriptions and annotations never grant permission or determine
side-effect classification. This intentionally supports a small schema subset by
explicit contract mapping, rather than interpreting arbitrary discovered schemas
or generating Python types from untrusted data.

Return an ordinary `TypedTool` with READ/READ_ONLY classification. The native
registry filters offers and rechecks both immutable run policy and separate operator
policy at dispatch. Native input validation and cooperative deadlines wrap the SDK
call. Require structured JSON output; validate it strictly against the local type,
then let the existing output boundary serialize and validate it again. Bound the
whole decoded MCP result to 64 KiB, including discarded content. Text, images,
resource links and metadata are never copied into model context. Remote error text
and SDK exceptions become existing fixed tool errors; cancellation propagates.
SDK schema-validation failures normalize to `tool_failed`, not guessed error types.

## Existing boundaries

Core commits tool intent before dispatch and persists outcome, step, checkpoint and
terminal state through the same store as native tools. Existing tool spans correlate
by invocation ID and omit payloads. Discard server stderr; suppress the SDK transport's
raw parse logs only in this connection's task context. Startup errors normalize to
`tool_resource_unavailable`. Discovery is operator setup before execution, not a
model action or persisted tool attempt.

No MCP writes, execution or external side effects are authorized. The `mcp.*`
namespace cannot impersonate the existing patch or sandbox capabilities. Existing
approvals bind exact proposals, workspaces and single-use intents; none authorizes
an MCP call. A future mutating MCP adapter must integrate an equally concrete
approval/effect contract before support is added. Read tools need the same two
grants as native reads, without inventing an approval prompt for reads.

## Limits and consequences

Stdio launches trusted operator-selected host code, not a sandbox. Calling a tool
read-only does not constrain a dishonest server. SDK environment inheritance and
process cleanup remain SDK behavior. It does not provide hard memory limits on
wire messages: catalog/result size checks run after decoding. Use only the public
fixture or equivalently trusted, resource-bounded local servers in this slice.

The in-process demo does not enroll worker jobs. No executable/content identity is
pinned for cross-process recovery; there is no MCP recovery profile, tool retry or
reconnect. Interruption preserves unresolved intent and restarting the in-process
runner refuses the already-running run. Tests verify this rather than claiming
automatic recovery. Bindings expire when their owning connection closes.

No migration, core configuration version, HTTP transport, OAuth, sampling, roots,
elicitation, resources, prompts, dynamic server registry or UI changes. The SDK's
default unsupported callbacks remain in effect; server messages are not delegated
to the agent. The public fixture proves protocol integration, not third-party
server safety, model quality or full Phase 11 closure.
