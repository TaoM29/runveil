# Local threat model and abuse analysis

Phase 15A, reviewed 2026-10-03 against the implementation through Phase 12B.
This is a bounded engineering assessment, not a claim of absolute security or
public-deployment readiness. [ADR 0044](../adr/0044-local-security-detour.md)
records the temporary sequence; Phase 12C live AWS acceptance remains paused.

## Assets and trust boundaries

Protect operator credentials, undisclosed host files, approval authority, durable
history, host/container resources and model/execution budgets. Repository text,
model actions, tool results, proposed code and test output are untrusted. Content
may affect the model's answer; it cannot supply operator grants, choose transport
configuration or constitute approval. Treat a model as fully persuaded by an
attacker when testing authorization, rather than relying on a safety prompt.

Trusted components are the application code, installed dependencies, operator,
PostgreSQL and local OS. Native handlers and operator-selected stdio MCP servers
are trusted host code. Docker daemon and reviewed immutable fixture image are
trusted; containers share the host kernel. Operator-controlled checkouts exclude
hostile concurrent writers/mount changes. These assumptions cannot be broadened
to arbitrary public repositories or multi-tenant execution without new review.

Flow: operator selects immutable profile and disclosure set; core intersects that
policy with separate operator grants; model receives selected observations; typed
dispatch validates the action and arguments; durable intent precedes execution;
approval and lease fences constrain mutations; outcomes/checkpoints record evidence.
The recorded web showcase imports two explicit public fixture artifacts. It has
no live run submission or worker execution path.

## Local disposition and evidence

15A selects T11 for a small production-code change and T1 for focused cross-boundary
regression evidence. T2–T10 already have concrete local controls and tests; their
residual risks are recorded rather than obscured by redundant validation layers.
15C records T12 policy without new execution authority. Verification and any
unrun checks are recorded in [the Phase 15 handoff](../operations/PHASE_15.md).

This review does not audit dependency vulnerabilities, remote infrastructure,
production authentication, IAM effectiveness, hostile-kernel isolation or live
provider billing. AWS-dependent controls and public deployment require the resume
order and later security gates in the [roadmap](../../ROADMAP.md).
